## 5. 已知差异（不是 bug）

### 5.1 联网搜索不生效
老客户端打开「联网搜索」会带 `use_rag:false` / `force_search:true`。新后端**不联网**，只走自有世界书检索，并记一条 `logger.info` 留痕。
- 客户端表现：回复正常、不报错；`knowledge_source` 返回 `worldbook`/`none`，不会是 `web`。
- 判定：契约兼容（字段照收、不报错），功能上「联网」这件事没做——属于**产品差异**，不是兼容缺陷。

### 5.2 SSE 的客户端自身 bug
老客户端的流式实现里有既有缺陷（收到 `delta` 之后出错不回退、`done.reply` 为空时的兜底逻辑等，见 `src/utils/backend.ts` 的注释），与后端无关；新后端 `delta` 拼接与 `done.reply` 严格一致，反而不会触发这些边界。

### 5.3 `/api/legacy-key` 相对路径在 `file://` 下取不到
`src/infra/http/legacyKey.ts` 里是 `fetch('/api/legacy-key')`（相对路径）。
- EXE（`file://`）：解析成 `file:///C:/api/legacy-key` → `TypeError: Failed to fetch`。**这是老包在 file:// 下的固有问题，不是新后端缺端点。**
- APK（`http://localhost`）：打到 Capacitor 本地服务器，返回 **200 + `index.html` 的 HTML**（不是 JSON），客户端 `resp.json()` 会失败。
- 结论：**新后端不需要补 `/api/legacy-key`**——老客户端在这两种宿主下都取不到它；这个端点只对「真有一个同源后端」的部署形态有意义。若将来要求老包能用内置 Key，需要改的是客户端取址方式，不是后端。

### 5.4 `/chat/suggestions` 在极短历史下可能返回空数组
2 条 history（约 1 轮）时实测返回 `[]`；4 条 history 时稳定 3 条；群聊推荐稳定 3 条。
- 客户端表现：面板显示「暂无推荐选项 / AI 回复后会自动出现在这里」，**不报错、不影响聊天**。
- 判定：契约合法（`suggestions` 始终是数组），属推荐质量边界。验收套件里因此用 4 条 history 的请求体断言「至少 1 条」。

### 5.5 老 EXE 的 `uploaded_at` 语义
服务端按 **UTC+8** 格式化（`_legacy_time`，固定偏移，不依赖 tzdata）。实测与上传时刻差 0.0 分钟，符合老客户端「显示上传时间」的用法。

### 5.6 kit 缺 `electron/` 目录
v3.2.2 kit 的 `package.json` 写 `main: electron/main.cjs`，但包里**没有 `electron/`**（kit 自带的 EXE 线是 `setup/tools/build.py` 打**安装器**，不是便携单文件）。兼容版构建脚本按 electron-builder 的期望布局，把 `setup/app/{main.cjs,preload.cjs,paths.cjs}` + `dist/` + `icon.ico` 铺进 `electron/` 再打 portable——这是**构建形态的差异**，不影响运行时行为（窗口/数据目录逻辑仍是 kit 原版 `main.cjs`）。

### 5.7 APK 的明文与 scheme
老包默认 `androidScheme='https'`，页面 origin `https://localhost`，打明文后端会被 mixed content 拦。兼容版改了**两处**（都在工作副本里）：
1. `capacitor.config.ts` → `server.androidScheme='http'` + `cleartext:true`；
2. `AndroidManifest.xml` → `android:usesCleartextTraffic="true"`。
只改一处不够：单改 manifest 仍会被 mixed content 挡，单改 scheme 仍会被 Android 9+ 的明文策略挡。**上生产必须走 HTTPS 才能还原老包的默认形态。**

## 8. 未验项

| 项 | 原因 |
|---|---|
| 物理手机（vivo V2502DA）装 APK | 本轮用 MuMu 模拟器（`127.0.0.1:16384`）替代；真机 USB 未连。模拟器已验证 ABI/明文/reverse/发消息，真机差异主要在厂商 WebView 版本（老包已针对 Chromium 83 做过兼容），**未实测** |
| APK 上的单聊 / 推荐 / 图片 / 云同步 UI 路径 | 模拟器输入注入限制（见 §6），只跑通了群聊；**协议层这四条全部 24/24 通过**，缺的是 APK 端的 UI 覆盖 |
| APK 首启 3 条对象型 console.error 的具体内容 | `description` 只有 `"Object"`，钩子重放拿不到（见 §3.2） |
| 老网页版 | 按用户口径不在验收范围（新 web 已重写） |
| 老客户端的 `system_prompt` 旧协议分支（未收录角色） | 需要一张"角色名不在 CHARACTER_ID_MAP 里"的自定义卡才能触发；本轮只用内置角色 |
| 群聊 `weighted` 模式 | 老客户端 3.2.2 只会发 round/smart/assign，`weighted` 是给新版留的口子，老包里到不了 |
