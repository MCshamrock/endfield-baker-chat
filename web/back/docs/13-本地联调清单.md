# 本地联调清单（改装老客户端 × 新后端）

> 2026-11-17。用途：拿**改装过服务端地址的老客户端**在本机打新后端，逐条验收。
> 目标不是"能聊一句"，而是**老客户端每一个功能在新后端上都不掉**。

## 1. 起服务（三步）

```powershell
cd F:\dshworkspace\BakerAI\BakerAI_new\web\back

# ① 数据库（便携版，端口 3307，不碰 3306）
pwsh -File scripts/dev_mysql.ps1 start
.venv\Scripts\python.exe scripts\migrate.py        # 幂等，跑到 017

# ② 起后端
.venv\Scripts\uvicorn.exe app.main:app --host 0.0.0.0 --port 5660
```

`--host 0.0.0.0` 是给**安卓真机**用的：手机和电脑不在同一个 loopback 上。
只有电脑上的 EXE 时用 `127.0.0.1` 就够，也少开一个防火墙口。

健康检查：`http://127.0.0.1:5660/readyz` —— 返回 `ok:true` 才说明库通了、迁移跑完了。

## 2. 客户端怎么指

| 客户端 | 填什么 | 注意 |
|---|---|---|
| Windows EXE（同一台机器） | `http://127.0.0.1:5660` | —— |
| 安卓 APK（同一局域网） | `http://<电脑局域网IP>:5660` | 要 `--host 0.0.0.0` + 防火墙放行 5660 |
| 网页版 | 同上 | 跨域已开（`allow_origins=["*"]`） |

查本机局域网 IP：`ipconfig` 找 IPv4（一般是 `192.168.x.x`）。

**改完地址要重启客户端**——很多老客户端把 base URL 缓存在本地配置里。

## 3. 逐条验收（按这个顺序打）

老客户端的调用全部走根路径，不经过 `/v1`。

| # | 功能 | 怎么试 | 通过标准 |
|---|---|---|---|
| 1 | 单聊非流式 | 发一句话 | 有回复，带括号描写（非沉浸式） |
| 2 | 单聊流式 | 打开流式开关发一句 | 字是**一段段蹦出来**的，不是一次性出现 |
| 3 | 沉浸式 | 打开沉浸式 | 回复里**没有**括号动作 |
| 4 | 图片 | 发一张图 | 能说出图里有几个什么颜色 |
| 5 | 不带图的历史不回放图 | 连发两轮 | 第二轮不会因为历史图变慢/报错 |
| 6 | 输入推荐 | 点开推荐面板 | 3 条候选，短句、第一人称 |
| 7 | 建群 | 3 个角色 | 返回 `session_id`、`members`、`ttl=300` |
| 8 | 群聊轮转 | `round` 模式发一句 | **每个成员各回一条**，`done=true` |
| 9 | 群聊智能 | `smart` 模式发一句 | 一次一条，`done=false` 表示该继续 |
| 10 | 群聊指定 | `assign` 指定某人 | 只有那个人说 |
| 11 | 群聊话题/关群 | 改话题、关群 | 改话题生效；关群后再发 404 `session_expired` |
| 12 | 运维端点 | 浏览器开 `/instances` | `modules.chat[0].status = healthy` |
| 13 | 能力声明 | `/v1/meta` | `capabilities.web_search = false` |

第 6 条容易误判：推荐是**点开面板才拉**的，不点就不发请求。

## 3.1 实测结果（2026-11-17 22:0x，改装 v2.4.1 客户端 × WSL 新后端）

驱动方式：CDP 连客户端（`--remote-debugging-port`），真实鼠标事件点组件、`execCommand` 输字、
回车发送；后端请求逐条对日志核。脚本在 `BakerAI_new/_runtime/tmp/`
（`client_send.mjs` 发消息、`cdp_click.mjs` 真鼠标、`cdp_upload.mjs` 塞图、`group_probe*.ps1` 群聊）。

| # | 功能 | 结果 | 证据 |
|---|---|---|---|
| 1 | 单聊非流式 | ✅ | `POST /chat 200`，人设正常，带括号描写 |
| 2 | 单聊流式 | ⚠️ 后端对、客户端坏 | `/chat/stream 200`，27 个 delta + done（`done.data.reply` 完整）；但界面在正常回复后**多弹一条**"回复内容为空" |
| 3 | 沉浸式 | ✅ | 开/关各发一句：开=纯台词，关=带 `(动作)` |
| 4 | 图片 | ✅（22:30 已接） | 客户端上传 → `POST /chat 200` → 明河答"红色圆日，配上 HELLO 42" |
| 5 | 历史不回放图 | ✅ | 带历史图（非本轮）与完全不带图，`prompt_tokens` 都是 **9401** —— 图没进 prompt |
| 6 | 输入推荐（单聊） | ✅ | `POST /chat/suggestions 200`，面板 3 条 |
| 7 | 建群 | ✅ | `session_id` / `members` / `ttl=300` 齐全 |
| 8 | round | ✅ | 3 人 3 条、`done=true`、3.6s |
| 9 | smart | ✅ | 1 条、`done=false` |
| 10 | assign | ✅ | 只指定那位说 |
| 11 | 话题 / 关群 | ✅ | topic 200；关群后发言 `404 session_expired` |
| 12 | `/instances` | ✅ | `status=healthy`，keys 47/25 |
| 13 | `/v1/meta` | ✅ | `capabilities.web_search=false`、`stream=true` |

群聊第 7–11 条是**协议级**验的（按 `groupBackend.ts` 的请求体直打），界面上的建群对话框没驱动。

### 两个要处理的

1. **流式那条是客户端自己的 bug**，不是后端。`useAiChat.ts` 把 `onUnplayable`（检查外层
   `fullText`）传进 `runBackendStream`，而 `fullText` 只在流式**返回之后**才赋值 ——
   于是开门就是空串，播完必然多一条"回复内容为空"。SSE 默认关，正常用户碰不到。
2. **图片没接**：老协议把图放在 `history[].image`（dataURL），`legacy.py` 没读。
   要接得注意"历史图不能每轮重发"，参考 `/v1` 的 `_image_of`（只认当前轮附件）。

### 顺手修掉的一个后端 bug

`legacy_group.py` 的 `session.last_speaker = name`（循环变量）在 smart 模式下会写成**候选名单第一个**，
而不是真正开口的那位（实测：回复是黎风说的、`last_speaker` 记成佩丽卡）。
已改成 `reply["speaker"]`；下一轮 prompt 里的「上一条是谁说的」也跟着对了。

## 4. 已知差异（不是 bug，别去查）

| 现象 | 原因 |
|---|---|
| 老客户端要"联网搜索"，实际没联网 | 新后端不做联网搜索（`docs/12`）。日志里会有 `老客户端请求了联网搜索…` |
| 群聊 `round` 一次吐好几条，慢 | 那是 N 次上游调用（老协议就这么设计的） |
| 回答 429 / "上游限速" | 每设备 12 次/分钟（只算 `generate`）。单人试不会撞，连点测试会 |
| 同一个会话反复测，越聊越慢 | 上下文到 16 万才开始压缩，正常会话撞不到；真撞到了看日志 `已压缩` |
| 第一次请求慢 3~5 秒 | 上游本身就这么慢（实测单条 2.7–4.9s） |

## 5. 出问题先看哪里

```powershell
# ① 进程活着吗、库通吗
curl http://127.0.0.1:5660/readyz

# ② 有没有真的打到后端（看访问日志里的路径）
#    老客户端打的是 /chat、/group/reply —— 出现 /v1/... 说明地址填错了

# ③ 钥匙池还活着吗（后台接口，需要管理员账号）
curl -H "Authorization: Bearer <token>" http://127.0.0.1:5660/v1/admin/overview
```

常见坑：

| 症状 | 原因 |
|---|---|
| `connection refused` | 服务没起 / 端口不是 5660 / 手机填了 127.0.0.1 |
| 所有请求 404 | 客户端把地址拼成了 `/v1/chat` |
| 回复是空的但 200 | 上游返回空内容（看日志 `上游返回了空内容`） |
| 中文乱码 | `.env` 里 `BAKER_DATABASE_URL` 少了 `?charset=utf8mb4` |
| 500 且日志提到 `api_keys` | `BAKER_SECRET` 变了 → 库里的 key 解不开 |

## 5.5 走 WSL 的起法（2026-11-17 实测可用，推荐）

本机 WSL2 的 Ubuntu 24.04 里跑后端，Windows 上跑改装过的老客户端 —— 比 Windows 直跑更接近
服务器（Linux + 真网络跳转），也顺手绕开了 Windows 侧 3307 端口被 Hyper-V 保留区间占用的问题
（WSL 一启动，Windows 的 3307 就会报 `Bind on TCP/IP port: 另一个程序…`）。

| 东西 | 位置 |
|---|---|
| 后端代码 | `F:\dshworkspace\BakerAI\BakerAI_new\web\back`（WSL 侧看是 `/mnt/f/...`，同一份文件） |
| 解释器 | `web/back/.venv-linux`（Python 3.12.3；装的是 `requirements.lock` 的**运行时段**，测试/lint 段里 `librt` 等是 3.14 专有，装不上也不需要） |
| 数据库 | WSL 里的**用户态 MySQL 8.0**，数据目录 `~/baker-mysql`，端口 3307，root 空密码（不需要 sudo） |
| 数据来源 | Windows 便携版库 `mysqldump` 出来的 `BakerAI_new\_runtime\baker_back_for_wsl.sql` |
| 启动脚本 | `_runtime\wsl_backend_db.sh`（起库+导数据）、`_runtime\wsl_backend_run.sh`（起 uvicorn） |
| 一键 | 双击 `BakerAI_new\local-client\启动.bat` |

要点：

- **数据目录必须在 Linux 原生盘**：放 `/mnt/f`（9p）时 mysqld 建 socket 直接报
  `Bind on unix socket: Operation not supported`（老账，别重踩）。
- 导数据是**幂等**的：库里已有表就跳过，想恢复初始数据加 `--force`。
- 依赖走**阿里云 PyPI 镜像**（实测 380 kB/s）；清华 8 kB/s，而且 `--extra-index-url pypi.org`
  会在每个包上额外等一次，慢得离谱 —— 镜像就写一个，别叠加。
- 客户端地址填 `http://127.0.0.1:5660`：WSL2 的 localhost 转发会让 Windows 的 127.0.0.1 直达 WSL。
- ⚠️ 从带 `ELECTRON_RUN_AS_NODE=1` 的终端启动客户端会白屏/秒退（Electron 被当成 node 跑，
  报 `bad option: --enable-logging`）。正常双击不受影响。
