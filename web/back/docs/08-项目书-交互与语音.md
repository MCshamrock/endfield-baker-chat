## 1. 单人模式的输入流程

单人模式的依次输入流程如下：

### 1.1 客户端输入

在客户端输入文本。其中的表情包会转成固定的 emoji 格式（例如：方括号里面加 emoji，加上该 emoji 所表达的情感）。同时，获取用户的手机时间，作为提示词一起输入。

### 1.2 发送至服务器

整个数据包发送到服务器，主要分为 3 部分：

- **第一部分**：用户真正说的话，直接发到 user 的输入 prompt 中。
- **第二部分**：提取出的时间，输入到 system 的 prompt 里面。
- **第三部分**：从用户的话中进行语义检索，跑一个算法，把检索结果输入到 system 里面。

实际上，prompt 的整个架构是没有变的，这些内容整理成一个完整的 prompt 后，通过 API 池轮询（也就是说，像某某站的 SK 就是用这个 API 发送 prompt），然后转到 agents。

### 1.3 图像与思考过程

至于用户的图像输入，我的想法是直接在用户本地将其转成 base64 编码，然后直接发到服务器，和 prompt 一起发到 agents 的服务器。

agents 2.5 flash 模型响应完之后，会输出一个 THINK（也就是思考过程）和一个正文。思考过程不对用户开放，只作为服务器的存储用，只存在服务器上。

正文采用正常角色扮演的格式，包含带括号的描写和说的话。这样我们就可以把它拆分成两个部分：

1. **语言部分**：如果是分段输出的，可以直接通过脚本拆分成小句，然后通过千问 3 的 TTS-Base-1.7B 进行语音转化。
2. **非语言部分**：即描写部分。

最后，我们将非语言部分和语言部分分别输出，连同生成的语音一起打包发到用户端。用户端这边会输出语言部分、描写部分以及音频部分，这就是单人模式。

## 2. 多人模式

至于多人模式，会有点复杂。首先，基本流程还是不会变的，只不过发言人的顺序我思考了一下，如果用户是多人模式，会有一个特殊的点：用户会去 @ 某一个干员。

因此，我们需要把这个 @ 的信息读取出来，并且前端要实现一个精准 @ 的功能。

### 2.1 @ 之后的发言逻辑

关于 @ 之后的发言逻辑如下：

1. 用户设置 active 值，这个值默认每个干员都是不同的，用户也可以自定义，值域为 1~100。
2. 使用这个 active 值加权进行随机数（random）计算，每次随机出来一个干员，就让这个干员说一句话。
3. 从随机数列表中将该干员删除，然后进行下一轮随机。
4. 如果有 @，优先处理 @。如果同时 @ 了好几个干员，同样通过 active 值加权随机，随机完之后，将该干员从 @ 列表和总列表中同时删除。
5. 每轮随机后，将消息 prompt 发给 Agent，Agent 回话后延迟两秒，再进行下一轮随机。这个延迟两秒非常重要。

### 2.2 输入流程

至于输入流程，还是跟单人模式一样：

用户说完一句话，就会自动调用发言逻辑，寻找下一个发言的是谁，直接将这个人设写入 system 的提示词，然后进行一轮请求。这一轮请求输出后，内容直接进入上下文，进行下一轮轮换，再次改变干员的 prompt 写入 system，进行下一轮，直到所有人发言完毕。

实际上，这里的重点是上一个干员说完话后，他的话要加入下一个干员的上下文中，这就需要通过 active 的值进行加权。

### 2.3 两秒延迟

最重要的是那个两秒的延迟：

1. 如果不加这个两秒延迟，服务器会炸。
2. 能够给用户一定的反应时间，这样会更加像一个真正的群聊。

OK。

## 3. 一句话总结这份文档

单人模式 = 文本 + 手机时间 + 语义检索 → 拼 prompt → 调上游 → 拆成「台词 / 描写 / 语音」三块回到客户端。
多人模式 = 单人模式 + **按 active 权重无放回随机选人** + **@ 优先** + **每句之间隔两秒**。

## 4. 转写疑点（我按什么理解）

| 原文 | 判读 | 依据 |
|---|---|---|
| `agents` / `Agent` | **Agnes**（上游模型服务） | 现网池子域名就是 `api.agnes-ai.cn`，模型名 `agnes-2.5-flash` |
| `agents 2.5 flash` | `agnes-2.5-flash` | 同上 |
| `TTS-Base-1.7B` | `Qwen3-TTS-12Hz-1.7B-Base` | `BakerAI/tts-lab/models/` 下就是这一个 |
| `某某站的 SK` | 占位，不影响理解 | 指"别的站也是用同一批 key 转发" |
| 「第 3 条：从随机数列表中将该干员删除」 | 属"本轮不重复"，不是跨轮记忆 | 与第 4、5 条连读才自洽 |

### 一处需要确认的张力

第 2.2 节说「直到所有人发言完毕」（像自动连发），
第 2.3 节又说「两秒延迟能给用户反应时间」。

我的判读是**可打断的连发**：2 秒内用户发话就掐断链条，改听用户的。
若是「每人一句就停下等用户」，那 2 秒就失去意义了。
