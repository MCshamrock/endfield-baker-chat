# 发言权重 · 使用与实现说明

> 状态：已落地（2026-11-18）。
> 对应工程：`BakerAI_new/web/back`。
> 一句话：**每个干员有一个"多爱开口"的权重；玩家可以按自己改，改完还能一键恢复默认。**

---

## 1. 权重从哪来：只有两层

| 层级 | 存在哪张表 | 谁改 | 作用范围 |
|---|---|---|---|
| **角色默认值** | `characters.active_weight` | 只有后台（`PATCH /v1/admin/characters/{slug}`） | 全局，所有玩家 |
| **玩家覆盖值** | `character_weights`（`owner_key + character_id + active`） | 玩家自己（`PUT /v1/characters/{slug}/weight`） | 只影响这个玩家 |

**有效权重**的定义只有一句话：

```
有效权重 = 玩家覆盖值（有就用它） ?? 角色默认值（没有就用它）
```

`owner_key` 就是"这份数据归谁"，规则和干员记忆完全一样：

- 登录了 → `u:<user_id>`（这个账号下所有设备共享）
- 没登录 → `d:<device_id>`（只在这台设备上有效）

所以：同一台手机换账号登录，权重不会串；换个账号就是另一套覆盖值。

## 2. 接口：读、改、恢复

### 2.1 读角色表 `GET /v1/characters`

这个接口**不需要 token**（首页要显示角色）。每个角色回三个权重相关字段：

| 字段 | 含义 | 会不会随玩家变 |
|---|---|---|
| `active_weight` | 角色**自带**的默认值 | 不会（只有后台能改） |
| `weight` | **有效值**：覆盖 ?? 默认 | 会 |
| `weight_source` | `"user"`（玩家改过）/ `"default"`（用默认） | 会 |

**带 token** 时：

```json
{
  "items": [
    {
      "id": "perlica",
      "name": "佩丽卡",
      "avatar": "",
      "attribute": "终末地工业",
      "active_weight": 50,
      "weight": 80,
      "weight_source": "user"
    }
  ]
}
```

**不带 token**（或 token 过期）时，`weight` 就等于 `active_weight`、来源一律 `default`。
公开接口不该因为"登录过期了"变成 401 —— 认不出人，就按默认值算。

> `active_weight` 保留不删，是因为老客户端只认它。新客户端请优先读 `weight`。

### 2.2 改权重 `PUT /v1/characters/{slug}/weight`

```json
// 请求
{ "active": 80 }

// 响应
{ "character_id": "perlica", "active": 80, "source": "user" }
```

- 必须带 token（这是"我的设置"，得知道我是谁）。
- `active` 允许 1~100；超出范围直接 400（模型层 `ge=1, le=100`）。
- 只写玩家覆盖表，**不会改角色默认值**。

### 2.3 恢复默认 `DELETE /v1/characters/{slug}/weight`

```json
// 响应
{ "character_id": "perlica", "active": 50, "source": "default" }
```

- 做的事情：删掉 `character_weights` 里这个玩家 × 这个干员的那一行。
- 删完 `GET /v1/characters` 看到的就是 `active_weight` / `default`。
- **幂等**：本来就没有覆盖行，也回 200，内容一样（`active` = 角色默认值）。
  客户端点「恢复默认」不该因为"你本来就没改过"而报错。

删除是**物理 DELETE**，不是软删：这张表只是"玩家的个人设置"，删掉就等于"没设置过"，
没有需要保留的历史。下次再 `PUT` 会重新插一行。

## 3. 对哪些模式生效

| 场景 | 读权重吗 | 说明 |
|---|---|---|
| 群聊 `speak_mode="weighted"` | **读** | 按权重加权随机抽下一位；权重越高越容易被抽中 |
| 群聊 `round` / `smart` / `assign` | 不读 | 轮转 / 主持人判断 / 玩家指定，都不该被权重影响 |
| 单聊 | 不读 | 单聊只有一个人，没有"选谁说话"这回事 |
| 老客户端群聊 `/group/reply` 的 `weighted` | **读** | 见 §4；老客户端不会发这个模式，这条只为两条链路语义一致 |
| 被 @ / 被点名 | 优先于人 | 点名优先，几个人都被 @ 时才在他们之间按权重抽 |

一句话记法：**权重只决定"群里这一轮轮到谁"，不决定"她说不说话"，更不影响单聊。**

## 4. 群聊选人现在怎么取权重

新版群聊（`app/group.py` 的 `_weights()`，`choose_speaker` 用它）：

```
先按成员 id 一次查出 characters.active_weight 作为底
再用 character_weights 里这个 owner_key 的覆盖值盖上去
→ {character_id: weight}
```

老群聊兼容层（`app/api/legacy_group.py` 的 `_weighted_rows()`）：

- 老协议里成员只有**中文名**、没有 slug/id → 先按名字回查 `characters` 拿真实 id；
- 再用同一个 `memories_repo.effective_weights()` 算覆盖值，口径和新版群聊**完全一致**；
- 请求带了 token 就按这个玩家算；**没带 token（老客户端本来就不带）就全部按角色默认值**；
- 名字在库里找不到（玩家自建角色）→ 用负数假 id 兜底、权重按 50，绝不会撞真 id。

这样「新版详情页显示的权重」和「实际抽人用的权重」是同一个数，不会出现
"界面写 80、抽人却按 50"的错位。

## 5. 会话详情里怎么读群成员权重

`GET /v1/conversations/{id}`：

```json
{
  "id": "3f2a...",
  "mode": "group",
  "members": ["佩丽卡", "陈千语"],
  "member_weights": [
    { "character_id": "perlica", "name": "佩丽卡", "weight": 80, "weight_source": "user" },
    { "character_id": "chenqianyu", "name": "陈千语", "weight": 50, "weight_source": "default" }
  ]
}
```

- `member_weights` 的顺序和 `members` **一一对应**（同 index 就是同一个人），前端可以直接 zip。
- 只有 **`mode="group"`** 才有内容；单聊是 `[]`（不是 null，前端少一个分支）。
- 建群响应 `POST /v1/conversations` 也会带（刚建完群就弹"调权重"界面，不用再请求一次）。
- 会话**列表**接口 `GET /v1/conversations` 为了省查询，只给成员名、`member_weights` 为空；
  要看权重请拉详情。

### 为什么不做成 `members` 对象数组

`members` 从第一版起就是**字符串名数组**（`["佩丽卡", "陈千语"]`）：

- 老客户端直接按名字读（头像、成员管理都靠它）；
- 既有测试 `tests/test_group.py`、`tests/test_imports.py` 也断言它是字符串数组。

为了塞权重把它改成 `[{id, name, weight, ...}]`，等于"为了加字段破老形状"。
所以另开一个平行字段 `member_weights`：老客户端不认识它就忽略，零风险；
新客户端要权重就读它，两个字段按 index 对齐。

## 6. 常见问题

**Q：为什么 `/v1/characters` 有时 `weight` 和 `active_weight` 一样？**
A：没带 token、token 失效，或者这个玩家没改过这个角色 —— 三种情况都按默认值算，
`weight_source` 会是 `"default"`。

**Q：改权重会影响别人吗？**
A：不会。覆盖值挂在 `owner_key` 上，只影响这个账号（或这台访客设备）。

**Q：后台改了默认值，玩家之前改过的 80 还在吗？**
A：还在。玩家覆盖优先；想回到新默认值，让玩家点一次「恢复默认」。

**Q：DELETE 两次会不会报错？**
A：不会，两次都 200。第二次只是"本来就没有可删的"。

**Q：权重 0 或 101 行不行？**
A：不行，接口直接 400。权重是 1~100 的整数；0 等于"禁言"，那是另一个功能，不做。
