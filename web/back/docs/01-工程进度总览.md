### 2.1 提示词实际结构（最重要的一张图）

```
[system] 安全协议          config.safety_protocol（热改，60s 缓存）
[system] 世界观            config.worldview
[system] 世界书索引        worldbook 366 条目录（设定/材料/人物；剧情不列，~2.7k token，可关）
[system] 世界书常驻        本世界书没有 constant 条目，此段为空
[system] 角色 + 风格规则    character_prompts(active=1) + EMPHASIS_RULE
[system] 前情提要          conversations.summary_head（**滚动摘要**：每次把「旧提要 + 新一段」重写成一份）
[system] 永久记忆          conversations.memory（只追加，绝不改写）
 …历史（seq > 摘要覆盖点；**超预算就压缩，绝不裁切**）…
[system] 检索正文          关键词预取，≤2000 token，插在最后一条 user 之前
[system] 【本轮附带图片】   仅带图时插入（否则角色会推掉图片）
[user]   本轮输入
```

**预算策略（2026-11-16 定）：默认 20 万 token，用户可设。**

- 历史和固定前缀加起来超预算 → 把最老的一段交给压缩器变成摘要，**不是从列表里扔掉**。
  扔掉的消息永远找不回来，而"她怎么不记得了"这种投诉没法解释。
- 触发线 = 预算 × 80%，压到 = 预算 × 50%（滞回，免得住每轮都压）。
- 每次最多压 30k token 的一段；单次摘要调用失败时**宁可超预算也不裁**，只记错误日志。
- 群聊走同一条路（`group.reply_once` 里调 `memory.compress_to_fit`），群聊记录不再有 40 条 / 4000 字符的硬裁。

## 3. 关键决策（别再重新讨论）

| 决策 | 结论 | 理由 |
|---|---|---|
| 语言/库 | Python 3.14 + FastAPI + SQLAlchemy 2 + MySQL 8.4 | 单进程单库，峰值 2.4 请求/分钟 |
| 状态归属 | 服务端唯一真相，客户端只发"会话指针 + 事件 + 幂等键" | C/S 翻转的前提 |
| **不限制并发人数** | 借不到 key 就 `acquire_waiting` 等（默认 20s），不 503 | 明确要求：不能因为人多就拒人 |
| 每设备限流 | 12 次/分钟（只算 `generate=true`） | 防脚本刷 key |
| **不上多线程** | 全链路 I/O 等待，asyncio 足够；进程 CPU ≤1ms/请求 | 见 §5 的实测数字 |
| 检索 | 三档（exact/fuzzy/semantic）**逐行移植**聊天终端内核 | 两端结果必须一致，不重写 |
| 记忆 | 摘要每次替换；永久记忆**只追加** | 允许重写就一定会删早期承诺 |
| key 加密 | AES-256-GCM，密钥在 `BAKER_SECRET` | 库泄露不等于 key 泄露 |
| 老客户端 | 无状态不落库 | 老客户端本来就不带 token，自己存历史 |
| **登录不换 token** | 登录只是给设备挂 `owner_user_id` | 客户端只有一套凭证；登录前聊的记录改一列就归账号，不搬数据 |
| **登录标识用用户名** | 用户名 + 密码，允许中文，大小写不敏感靠库的 `_ai_ci` | 没有发信能力，邮箱没用处；玩家不该为注册去拼英文邮箱 |
| 数据归属 | 登录态按 `user_id` 查；访客按 `device_id` + `user_id IS NULL` | 换设备看得见、登出看不见、换账号不串数据 |
| 密码 | 标准库 `hashlib.scrypt`（N=16384 r=8 p=1），`scrypt$N$r$p$salt$hash` | 不引编译型依赖，`requirements.lock` 与服务器保持一致 |

## 5. 踩过的坑（都写进代码注释了，别再踩一遍）

| 坑 | 现象 | 原因 |
|---|---|---|
| WSL 跑 MySQL | `Bind on unix socket: Operation not supported` | 数据目录在 `/mnt/d`（9p 不支持建 socket）→ 改用 Windows 便携版 |
| `mysqladmin ping` 判存活 | 明明连到了别的实例还说 alive | ping 对"密码错"也返回 0 |
| `my.ini` 少了 `[client]` | 客户端连到 3306（别人的库） | 端口没写进客户端段 |
| `skip-name-resolve` | `Host '127.0.0.1' is not allowed` | 127.0.0.1 不再反解成 localhost |
| 启动脚本卡住 | `dev_mysql.ps1 start` 不返回 | 子进程继承了 stdout 管道 |
| `keys` 列名 | 建表 1064 语法错 | `keys` 是 MySQL 保留字，要反引号 |
| 全局附件去重 | 新设备传同一张图拿到别人的记录 → 404 | 唯一键从 `sha256` 改成 `(device_id, sha256)` |
| 角色推掉图片 | 回"我无法查看图片" | 人设挡的；裸问能看清 → 带图时插一句"你能看到" |
| 沉浸式失效 | 开关开了还是满屏括号 | 必须**整段截掉**风格规则，不是追加一句禁令 |
| 表情被当动作删掉 | 沉浸式下表情全没 | 先翻译表情（生成括号）再过滤括号，顺序反了 |
| 群聊被点名却换人 | 说"佩丽卡你来说"，接话的是别人 | 模型看到了名字但不照做 → 点名改成代码判定 |
| `api_key_id` 一直为空 | 粘性无法核对 | 记账时漏传，已补 `Generation.api_key_id` |
| 配额被误伤 | 重发/只存不发也被计数 | 限流放在幂等判断之后、只算 `generate=true` |
| 测试跑得很慢 | 全量 118 用例约 6 分钟，中途 `SHOW PROCESSLIST` 看着像卡在 `TRUNCATE` | 每张表 TRUNCATE 0.1–0.6 s（重建表空间），13 张 × 118 例 ≈ 6 分钟，**不是死锁** |
| 模型与迁移不一致 | `attachments` 模型写全局 `sha256` 唯一，库里是 `(device_id, sha256)` | 011 改了库没改模型；`test_schema` 只比表和列，没比索引 ⇒ 已改模型 |
| 群里「新话题」行 | 导入后被当成玩家说的话，模型回得很奇怪 | 用 `side='system'` 存，`list_before_seq` 跳过 system 行 |
| 历史图片看不见 | 重新进会话，图片消息是一条空白气泡 | `MessageOut` 没带附件；已加 `attachment_id` / `attachment_url` |
| 用户名规则写漏 | `_abc` 被当成合法用户名（正则首字符允许了下划线） | 首字符只允许中文/字母；前后端提示必须同一句 |
| ENUM 加值要迁移 | 模型里加了 `login_type='username'`，库里还是旧的三个值，注册直接 1265 报错 | `schema/014` 用 `MODIFY COLUMN` 扩枚举；**模型与迁移必须同一次改** |

## 6. 实测性能（本机，国内站 key）

```
拼提示词               0.6 ms        ← 我们自己的全部 CPU 开销
单发非流式             2.7 – 4.9 s   ← 上游 TTFT 占绝大部分
SSE 首字 / 整段        4.8 s / 5.5 s
8 并发（同一设备）      3.0 – 16.7 s，8/8 成功
站点对比               国内 1.52 s  vs  国际 3.10 s（已优先国内站）
提示词规模             9.4 – 9.9k token（含世界书索引与预取；cached 常命中 8k+）
```

**结论：慢在上游，不在本机。** 多线程/多进程对单条延迟没有帮助（进程 CPU 只占 1 ms）。

## 7. 安全注意

1. `BAKER_SECRET` 现在是本机 `.env` 里随机生成的；**换它 = 已存 key 全部解不开**。
2. `api_pool.json` 里 47 把 key 是**明文**躺在 `原始网站前后端/backend/api/`。库里的已是密文，那个文件建议挪走或删掉。
3. 22 把 `enabled=0` 的 key 是供应商侧未实名/封号，**明确不要启用**。
4. 老客户端兼容层是**无鉴权**的（`/chat` 不需要 token）——上线前必须靠网关限流兜住，否则任何人都能拿它刷你的 key。

## 8. 下一步建议

按"能不能当产品用"排：

1. **后台 + 指标 + 备份**（P1，挡住"出问题只能翻日志"和"数据零备份"）
   —— 登录做完之后，**改阈值还只能改 `.env` 重启**，这是现在最难受的一处；
   而且项目数据依然零备份。
2. **`/group/*` 兼容**（P2，等老客户端或新客户端决定）
3. 工具化检索（让模型能主动查世界书，而不是只靠预取）
4. 设备绑定码 / 找回密码（P3，都属于"锦上添花"，有人抱怨再做）

如果要先给用户用，最短路径是：**后台 → 备份**，然后把 nginx 反代和 TLS 接上（那一层还没做，`proxy_buffering off` 要给 SSE 留着）。
