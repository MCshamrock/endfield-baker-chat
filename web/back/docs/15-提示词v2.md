# 15 · 提示词 v2（`use_new_prompt`）与老客户端兼容补齐

> 一句话：老客户端的 `use_new_prompt` 开关现在真的生效了 ——
> 打开读 `characters_v2/`（实验性长卡，`variant=v2`），关着仍读原来的卡（`variant=v1`）；
> 某个角色没写 v2 时自动回落 v1。顺带把兼容层几处"老客户端会踩到"的行为补齐了。

---

## 1. 两套提示词是什么

| 变体 | 来源 | 谁在用 |
| --- | --- | --- |
| `v1` | 老包 `characters/*.json`（已在新库 `character_prompts.body`） | 默认；`/v1/conversations/*` 等新链路、老客户端开关关着 |
| `v2` | 老包 `characters_v2/*.json`（实验性长卡） | 只有老客户端把 `use_new_prompt` 打开时 |

老后端的规则（新后端照做）：

```
use_new_prompt = True → 读 characters_v2/
                       找不到这个角色 → 回落 characters/（v1），只记一条 warning/debug
```

所以**不是每个角色都必须有 v2**。没有 v2 的角色照样能说话，只是用 v1。

---

## 2. 数据库：`schema/019_prompt_variant.sql`

给 `character_prompts` 加一列：

```sql
variant VARCHAR(8) NOT NULL DEFAULT 'v1'   -- 'v1' / 'v2'
```

加列时 `DEFAULT 'v1'` 会把已有的行全部自动填成 v1，不需要搬数据。

### 为什么非要换唯一键

原来唯一键是 `(character_id, ver)`。两套提示词的「第 1 版」都叫 `ver=1`：

```
v1: (perlica, ver=1)  ← 已经存在
v2: (perlica, ver=1)  ← 会撞唯一键，插不进去
```

所以迁移把它改成 **`(character_id, variant, ver)`**：变体进键里，两套各存各的。
查询用的普通索引也换成 `(character_id, variant, active)`，正好对应取词条件。

⚠️ 语句顺序不能反：**先加列 → 再换唯一键 → 最后换索引**。
先建带 `variant` 的键会报 `Unknown column 'variant'`。

## 3. 导入脚本：`scripts/import_prompts_v2.py`

### 用法

```bash
# 在 web/back 目录下；连哪个库由 BAKER_DATABASE_URL / .env 决定
.venv-linux/bin/python scripts/import_prompts_v2.py --dry-run   # 只看会做什么
.venv-linux/bin/python scripts/import_prompts_v2.py             # 真写库
```

老包不在默认位置时加 `--source /path/to/characters_v2`。
默认位置按脚本自身路径推算：`<BakerAI>/原始网站前后端/backend/characters/characters_v2`。

### 三条硬规矩

1. **逐字节写入**：`json.loads` 把 JSON 里的 `\n` 还原成真实换行，写库时
   **不 strip、不二次转义**。老客户端读到的就是这些字节，多一个空格都算改人设。
2. **角色靠 `characters.slug` 对齐**：文件名去掉 `.json` 就是 slug
   （`perlica.json` → `perlica`）。库里没有这个 slug 就跳过并打印警告，绝不乱挂。
3. **幂等**：按 `(character_id, variant)` 找已有行 —— 有就更新正文，没有才插入
   （`ver=1`、`active=1`）。重复跑不会多出第二套 v2。

`index.json`（目录清单）和 `.bak` 文件会被跳过。

### 本机导入结果（`baker_v2`）

| 变体 | 行数 | 正文字符合计 | 正文字节合计 |
| --- | --- | --- | --- |
| v1 | 36 | 211,615 | 576,703 |
| v2 | 36 | 299,366 | 813,936 |

抽查（v1 字数 → v2 字数）：

- 佩丽卡 `perlica`：4,656 → 9,385
- 黎风 `lifeng`：5,265 → 8,256
- 管理员 `endministrator`：8,678 → 8,678（**老包这两份完全一样，不是导入错误**）

## 4. 取词层：`app/repos/content.py`

```python
get_active_prompt(db, character_id, variant="v1")          # 取词
get_character_prompt(db, character_id, device_id=None, variant="v1")
```

- 查询条件：`character_id + variant + active=1`，同版本取 `ver` 最大的一条。
- **v2 取不到 → 回落 v1**，返回 v1 正文并记一条 `debug` 日志（正常情况，不刷 warning）。
- **提示词查询没有缓存**（只有安全协议有 60 秒缓存）。这是故意的：
  每轮一次索引查询、开销可忽略；缓存反而会让"刚导入的 v2 一分钟内取不到"，
  还多一类"v2 串到 v1"的坏法。将来真要加缓存，键必须是 `(character_id, variant)`
  两段一起，并且 `clear_cache()` 要连它一起清。

设备级覆盖（`device_prompts`，用户在客户端亲手改过的人设）**优先级高于任何预设**，
命中时不再看 variant —— 用户自己写的文本不能被"打开新提示词"覆盖。

## 5. 老客户端链路

| 入口 | 行为 |
| --- | --- |
| `POST /chat` | `use_new_prompt=True` → v2；否则 v1 |
| `POST /chat/stream` | 同上（共用 `_build_messages`） |
| `POST /group/reply` | 同上；**同一次 round 里每个发言人都用同一个 variant** |
| `/v1/conversations/*` 等新链路 | **保持 v1 不动**（`variant` 默认值就是 `"v1"`） |

## 6. 老客户端兼容补齐（本次一起做）

> 背景：用户把"老客户端零错误"定为 P0。下面每一条都对照过老后端
> `prompt_core.py` / `group_chat_service.py` 的实际实现。

| 项 | 老后端行为 | 新后端（现在） | 测试用例 |
| --- | --- | --- | --- |
| A1 `character_prompt` | 用户覆盖 > 角色卡 > `system_prompt`；覆盖时不再用库里的卡 | 已修：字段收下；有覆盖就只用它，不拼卡 | `test_legacy_character_prompt_overrides_the_card` |
| A2 `system_prompt` | 未收录角色（没有卡）也能出话，不 404 | 已修：没有卡但带 `system_prompt` 就照常出话 | `test_legacy_system_prompt_fallback_without_card` |
| A3 三者皆空 | 才是"没有这个角色" | 已修：仍 404 `no_character`（空白串算没有） | `test_legacy_all_prompts_empty_is_still_404` |
| B round 单成员失败 | 逐成员 try，失败写 `{speaker, text:"", error}` 占位，其余照说，200 + done | 已修：失败只留占位；**429 仍上抛**（老服务也这样） | `test_round_member_failure_does_not_kill_the_round` |
| C assign 点到玩家角色 | `replies: []` + `done: true` + `stop_code="player_role"` + 中文 stop_reason | 已修：不再换别人顶替 | `test_assign_player_role_is_not_replaced` |
| D 累计轮数上限 | `MAX_TOTAL_TURNS = 600`，`stop_code="max_total_turns"`，`new_turn` 清不掉 | 已修：`total_turns >= 600` 就收摊 | `test_total_turns_cap_stops_the_group` |
| E 群聊图片占位 | `side=other` 的纯图 → `[图片]`；玩家纯图 → `[玩家发来一张图片]` | 已修：作为文字进 transcript / 本轮输入 | `test_group_image_history_becomes_placeholder` |
| F smart 判 END | **不结束**：换成"上一位的下一位"，附 `NUDGE_CONTINUE` 续接；只有 `MAX_TURNS` 才 done | 已修（文案逐字照抄老服务） | `test_smart_end_continues_instead_of_stopping` |

### 两处"故意和老后端不完全一样"

1. **`character_prompt` / `system_prompt` 一个字都不加。**
   老后端在正文缺 `### 回复风格规则` 时会补 `EMPHASIS_RULE`；新后端按
   "前端给的是整段人设"处理（`build_dialog_messages(character_prompt_is_final=True)`），
   不再补任何规则。原因：覆盖卡是用户亲手写的，服务端往里塞规则等于改人家的卡。
   如果以后发现老客户端非沉浸式下确实需要那段规则，把 `character_prompt_is_final`
   的传参去掉即可回到老行为。
2. **F 的"续接"由 `_one_reply` 内部完成**（主持人判 END → 选下一位 + nudge），
   `_run_round` 不再把 `None` 当成"该停了"。旧测试
   `test_smart_stops_when_judge_says_end` 已按老行为改名/改写
   （`test_smart_end_continues_instead_of_stopping`）。

## 8. 风险 / 注意事项

1. **v2 是实验性内容**，来自老包原样导入，没有校对。要改就改老包再重跑脚本（幂等），
   别直接手改数据库。
2. **管理员（endministrator）的 v2 与 v1 完全相同**（都是 8,678 字），这是老包的事实，
   不是导入漏了。想验证导入是否正常，看 perlica/lifeng 的差异即可。
3. 迁移**没有 downgrade**。上线前先 dump；回滚靠备份。
4. `variant` 默认值是 `'v1'`：旧代码插入提示词时不带这个字段也不会撞键，行为不变。
5. 兼容层的行为变化（F 的 smart 不再自动结束、B 的 round 不再整轮 502）是**照老后端改的**，
   会改变新后端之前的表现；如果新客户端依赖旧行为，需要提前对齐。
6. `character_prompt` / `system_prompt` 不补规则（见 §6 末尾），属于有意取舍。
