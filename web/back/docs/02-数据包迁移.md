# 老数据包迁移（导入）设计与验收

> 2026-11-15 · 对应代码：`app/imports/`、`app/api/imports.py`、`schema/012`、`schema/013`
> 前提：老客户端（APK/EXE）和老网页版都能「导出数据」，用户手上已经有包了。
> 目标：把包导进新后端，**一条聊天记录都不丢**；丢了的必须能说清为什么。

---

## 1. 包长什么样

老客户端 `utils/zipExport.ts` 产出两种，新后端**两种都吃**（按内容判断，不看扩展名）：

### 1.1 `.zip`（体积小，推荐）

```
project.json                          版本、我的性别、设置快照、群聊卡片元数据、列表顺序
cards/00/conversations/00-伊冯.json    每段对话：messages + contextHistory
cards/00/images/00-3.png              图片消息的本体（JSON 里只留包内路径）
prompts/characters/伊冯.txt            用户自己改过的角色提示词（仅自定义时有）
```

### 1.2 `.json`（单文件，图片内联 dataURL）

```jsonc
{
  "version": 1,
  "cards": [ { "conversations": [ { "name": "伊冯", "messages": [...] } ] } ],
  "myGender": "male",
  "promptOverrides": { "伊冯": "……" },
  "settings": { "...": "..." },
  "order": ["s:伊冯", "g:伊冯|佩丽卡|管理员"]
}
```

### 1.3 老版本的字段别名（全部兼容）

| 东西 | 认得的名字 |
|---|---|
| 卡片数组（顶层） | `cards` / `characterCards` / `characters` / 顶层裸数组 |
| 子对话 | `conversations` / `subs` / `children` |
| 消息数组 | `messages` / `items` |
| 消息正文 | `text` / `content` |
| 消息方向 | `side: mine\|other` / `role: user\|assistant` |
| 说话人 | `speakerName` / `speaker` |
| 群成员 | `members` / `groupMembers` / `group_members` / `memberNames` / `memberList` |
| 群字段嵌套 | 也可能整组塞在 `group` / `groupInfo` / `groupMeta` / `groupConfig` 里 |
| 自定义提示词 | `promptOverrides` / `prompts` |

## 2. 一张卡片变成什么

**一个子对话 = 一个新会话。** 老客户端是"一张主卡挂多段子对话"（像存档），
新后端是平铺列表。一段存档建一条会话，用户点进去看到的就是那一段，
不会把几条不同时间线的对话糊成一条。

| 老包 | 新库 |
|---|---|
| 单聊卡（无 `members` 或不足 2 人） | `conversations.mode='single'`，用**角色名**换 `character_id`，标题 = 角色名 |
| 群聊卡（`members` ≥2） | `mode='group'` + `conversation_members`；`speakMode` → `speak_mode`，`myRole` → `player_role` |
| `messages[].side` | `mine` → `user`，`other` → `assistant` |
| `messages[].topic = true` | `side='system'`（屏上显示，**不进 AI 上下文**） |
| `messages[].isError` | 丢掉（请求失败的占位气泡，本来就不是聊天记录） |
| `messages[].image` | dataURL 或 ZIP 内路径 → 落盘成附件，挂到 `messages.attachment_id` |
| `messages[].mood` | `messages.mood` |
| `prompts/characters/*.txt` | `device_prompts`（**只影响这台设备**，不动全局人设） |
| `order` | 不直接存；按 `cards` 数组顺序给 `last_active_at` 递减，列表顺序照旧 |
| `myGender` / `settings` | 不迁移（新后端没有这两处状态），只记进批次报告 |

### 2.1 认不出的角色怎么办

老包里只有中文名。名字在 `characters` 表里查不到时（用户改过名、或是没收录的角色）：

* **照样建会话**，只是 `character_id = NULL`、标题用老包里的名字；
* 历史消息一条不少，可以当普通对话接着聊，只是没有那个人的人设；
* 响应里的 `notes` 会点名说是哪几个角色。

顺序很重要：**丢人设是小事，丢历史是大事。**

### 2.2 `contextHistory` 去哪了

老包同时存了"屏上消息"和"AI 记得的历史"，两者可以各自清空，所以会不一致。
新后端只有一套消息，规则是：

* 屏上消息非空 → **以屏上消息为准**（用户认的是屏上那份），`contextHistory` 丢弃并计数；
* 屏上消息为空、但 `contextHistory` 有内容（用户清空过消息）→ **用 `contextHistory` 兜底**，
  否则这段记忆就彻底没了。

## 3. 接口

```
POST   /v1/imports              multipart：file=<包> + mode=merge|replace
                                → 201 {id, duplicate, source, cards, conversations,
                                        messages, images, skipped, notes[], created_at}
GET    /v1/imports              这台设备的导入历史（最近 50 次）
DELETE /v1/imports/{id}         撤销这次导入（只软删它建的会话）
```

* **鉴权**：必须带 `Authorization: Bearer <device token>`。包内容是匿名的，
  但"导进谁名下"由 token 决定。
* **体积上限**：64 MB（老客户端导出侧硬上限 60 MB，留了余量）。上传是分块读的，
  超限在第一兆就拒，不会把进程内存吃满。
* **`mode=merge`（默认）**：新增，不动已有会话。
* **`mode=replace`**：先把这台设备现有会话全部软删，再导入 —— 和老客户端"覆盖导入"同语义。

### 3.1 前端要知道的两件事

1. **带图消息靠 `attachment_id` 取图。** `GET /v1/conversations/{id}/messages` 里每条消息
   都带 `attachment_id` + `attachment_url`（没有图就是 `null`）。拿 `attachment_url`
   去请求会校验归属，别自己拼文件路径。老包的图片最多，这一条不做的话重新进会话
   就是一条条空白气泡。
2. **同一角色的多段存档，在新库里是同名会话。** 老客户端把"一个角色的多段对话"放在
   一张卡的标签页里，名字都等于角色名；新后端平铺之后会出现几行一样的标题。
   列表必须显示"最后一条消息 + 时间"来区分，不能只显示标题。

### 3.2 幂等与撤销

* 包内容的 sha256 就是幂等键（`uk_batch_device_fp`）。**同一台设备传同一个包第二次**，
  直接回上次的结果，`duplicate: true`，不会建两遍。
* 每条导入的会话都记着 `conversations.import_batch_id`。撤销按批次整体软删，
  **用户自己聊的会话一条都不动**。
* `mode=replace` 的那次软删和导入在**同一个事务**里：导到一半炸了就整体回滚，
  不会出现"旧的没了、新的没进来"。

## 4. 明确没迁移的东西（都写进 `notes` 了）

| 项 | 为什么 | 影响 |
|---|---|---|
| `contextHistory`（不一致时） | 与屏上消息冲突，只能选一个 | AI 记不住"只清过屏上消息"的那部分 |
| `myGender` | 新后端没有这个状态 | 老客户端里"管理员性别"的选择不带过来 |
| `settings` 快照 | 那是客户端本地配置（API 地址、开关） | 新客户端本来就不该沿用旧配置 |
| `suggestions`（AI 推荐缓存） | 一次性结果，过期即失效 | 无影响 |
| `groupSessionId` | 老后端会话 300s 就回收了，跨重启必失效 | 无影响 |
| 单条消息的时间 | 老包只有数组顺序，没有时间戳 | 导入的消息 `created_at` = 导入时刻，顺序靠 `seq`；`origin='legacy'` |

### 6.1 三个顺带修掉的东西

1. `messages_repo.list_before_seq` 现在**跳过 `side='system'` 的行** —— 否则导入进来的
   「新话题」提示行会被当成玩家说的话喂给模型。屏上能看到的和喂给模型的，在这里分开。
2. `app/models/chat.py` 里 `attachments` 的唯一键改成 `(device_id, sha256)`，
   和迁移 011 的实际情况对齐（模型原来还写着全局 `sha256`，属于两边不一致）。
3. `GET /v1/conversations` 现在**带群聊成员**（一次查询批量取，不是 N+1）；
   `GET .../messages` 带 `attachment_id` / `attachment_url`。
   这两条不做，导入进来的群聊没法画头像叠层、图片消息没法显示。
