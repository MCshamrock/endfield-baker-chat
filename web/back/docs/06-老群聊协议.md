# 老群聊协议（`/group/*`）—— 兼容层实现说明

> 2026-11-16。来源是老服务 `group_chat_service.py`（生产 `perlica_group`，5810）。
> 新实现的落点是 `app/api/legacy_group.py`，六个端点字段逐字对齐。

## 0. 一句话

老客户端的群聊**不是** `/v1/conversations` 那套东西：它不建会话、不落库，
每轮把整段 history 传上来，服务端回答"这次谁说话、说什么"。
这一层就是把它接住，老客户端一行不改。

## 1. 六个端点

| 方法 | 路径 | 作用 | 关键字段 |
|---|---|---|---|
| POST | `/group/session` | 建群 | `members`、`my_role`、`speak_mode`、`assign_target`、`topic`、`group_name` |
| POST | `/group/reply` | 取"下一步" | `session_id`、`history`、`topic`、`new_turn`、`members`/`speak_mode`/`assign_target`/`my_role`（带就地生效） |
| POST | `/group/suggestions` | 输入推荐 | `session_id`、`history` |
| POST | `/group/topic` | 改话题 | `session_id`、`topic` |
| POST | `/group/session/close` | 关群 | `session_id` |
| GET | `/group/sessions` | 调试：当前会话 | 无 |

`history` 的每一项：`{"side": "mine"|"other", "text": "...", "speaker": "佩丽卡", "image": ""}`。
`image` 老协议里有，这一版忽略（图走 `/v1` 的附件）。

## 2. `done` 语义（最容易搞错的地方）

| 模式 | 返回几条 | `done` 的含义 |
|---|---|---|
| `round` | **全员各一条** | 恒为 `true`（一轮发完） |
| `assign` | 指定那位一条 | 恒为 `true` |
| `smart` | 一条 | `false` = 前端该接着请求；`true` = 该停了（主持人判 END / 到轮数上限 / 没有可说话的 AI） |

`round` 是整条协议里唯一"一次请求多次调用上游"的模式 —— 必须照做，
少说一个人老客户端就会以为"有人没说话"。

## 3. 响应形状

```json
{
  "ok": true,
  "session_id": "…",
  "speak_mode": "smart",
  "replies": [
    {"speaker": "佩丽卡", "text": "…", "need_search": false,
     "knowledge_source": "worldbook", "usage": {"prompt_tokens": 0, "completion_tokens": 0}}
  ],
  "suggestions": ["嗯。", "然后呢？", "我知道了。"],
  "done": false,
  "last_speaker": "佩丽卡",
  "stop_reason": "",
  "stop_code": ""
}
```

`stop_reason` / `stop_code` **恒存在**（不停止时是空串）—— 老前端只判"有没有值"，
不会先判键在不在，少一个键就少一处漏判。

`stop_code` 取值：`max_turns`（到单次连续轮数上限）、`no_ai_member`（群里没有可被 AI 接管的成员）。

## 4. 错误

```json
{"error": "会话不存在或已超时,请重新创建群聊", "code": "session_expired", "session_expired": true}
```

| HTTP | code | 什么时候 |
|---|---|---|
| 400 | `bad_members` | 成员少于 2 |
| 400 | `bad_speak_mode` | 模式不认识 |
| 400 | `bad_my_role` | 身份既不是 observer/admin，也不在群里 |
| 404 | `session_expired` | 会话不存在或超过 300 秒没动 |
| 429 | `session_limit` | 会话数到 200 |
| 429 | `rate_limit` | 上游限速 |
| 502 | `upstream_error` | 其他上游失败 |

## 5. 和老服务的三处差异（老客户端无感）

| 差异 | 老服务 | 新后端 | 为什么可以不同 |
|---|---|---|---|
| 会话存哪 | SQLite（多 worker 共享） | 进程内字典 + TTL | 我们是单进程；少一个文件少一种坏法 |
| 提示词 | 老的一套（联网搜索/旧语料库） | 新后端群聊分层 + 世界书预取 | 响应结构不变，回答只会更贴设定 |
| 用量 | 有 api 分配统计 | 不记 | 老契约没有额度概念，硬记会污染账单 |

## 6. 与 `/v1` 的关系

两条路互不影响：

- **老客户端** → `/group/*`（无状态、历史在客户端本地）
- **新客户端** → `/v1/conversations`（服务端持有历史、压缩、干员记忆、发言权重）

共存期用 nginx 按路径分流即可，不需要改任何一端。
