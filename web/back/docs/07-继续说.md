# 继续说（`POST /v1/conversations/{id}/continue`）

> 2026-11-17。玩家不想打字、或者她话没说完时，点一下让她接着往下写。

## 0. 一句话

**不产生用户消息，只产生一条新的 assistant 消息。**

不这么做的话（比如让客户端发一条空消息）会带来三个问题：历史里多一条空气泡、
seq 被白占一个、下次压缩会把这条空消息也压进去。

## 1. 请求 / 响应

```http
POST /v1/conversations/{public_id}/continue
Authorization: Bearer <device token>

{"client_msg_id": "cont-20261117-0001", "local_time": "2026-11-17 00:20 周一", "think": false}
```

```json
{"reply": "（把杯子放下）……", "reply_seq": 12, "duplicate": false,
 "usage": {"prompt_tokens": 9123, "completion_tokens": 180, "cached_tokens": 8800, "total_ms": 3120},
 "created_at": "2026-11-17T00:20:31+00:00"}
```

| 字段 | 说明 |
|---|---|
| `client_msg_id` | **幂等键**，必传。重放同一个 id 不会生成第二段 |
| `local_time` | 同普通消息，进【现在】那一段 |
| `reply_seq` | 这条新回复的 seq（客户端直接追加气泡） |
| `duplicate` | `true` = 这是重放，服务端没有再调上游 |

## 2. 提示词怎么改的

只加一条**用户消息**（`app/prompt/rules.py::CONTINUE_RULE`），其余（世界观、角色、人情账、
前情提要、历史、检索、压缩、key 池、记账）和普通回复**完全一样** —— 少一样就是两套逻辑。

为什么写进 user 而不是 system：OpenAI 兼容端对"最后一条是 system"支持不一，user 在哪儿都收。
内容是 OOC 指令，所以用【系统指令】框起来，免得模型当成玩家在说话。

指令的四条（每一句都对应一种线上会翻车的表现）：

1. 不要重复、不要总结、不要重新打招呼、不要换话题 —— 不然模型会把上一段重说一遍；
2. 话说一半停的就接着说完；
3. **已经说完了就推镜头**（她做了什么、看向哪里、又补了一句什么）—— 这条最容易被忽略，
   用户点"继续"的时候，上一段往往已经是完整的一段话了；
4. 篇幅语气跟刚才一致，约 150~300 字。

## 3. 幂等怎么做的

assistant 消息平时用 `a:{seq}` 当 `client_msg_id`（表上有 `(conversation_id, client_msg_id)` 唯一键）。
「继续说」改用 `cont:{client_msg_id}`：

- 重复请求 → 先按这个键查，查到就原样回放（`duplicate: true`），不再调上游；
- 并发重试 → 唯一键兜底，第二次插入会撞键，不会出现两条一模一样的回复。

## 4. 边界

| 情况 | 行为 |
|---|---|
| 会话里还没有任何角色发言 | 400 `nothing_to_continue`（先聊一句） |
| 群聊 | 400 `continue_unsupported` —— 群里"继续"要先选"谁接"，见下 |
| 上游失败 | 502 `upstream_error`（不会留下半截消息） |
| 触到限流 | 429（和普通消息同一道闸门，只算 `generate`） |

## 5. 群聊走另一个端点

群里"继续"有两种意思：让**刚才那位**接着说、或者让**下一位**接话。
后者不是"继续"，是**推进一轮**，单独一个端点：

```
POST /v1/conversations/{id}/next   →  {"reply": "...", "speaker": "佩丽卡",
                                      "done": false, "remaining": ["陈千语"]}
```

客户端发完一句 → 收一条 → 等 **2 秒** → 调 `/next` 要下一位 → 直到 `done=true`。
权重随机、@ 优先、本轮无放回都在服务端（见 docs/06 §2 与 docs/08 §2.1）。

让"刚才那位接着说"目前只有单聊的 `/continue`；群里要这一能力时，
把 `/next` 加一个 `speaker` 参数就够（现在已支持指定谁说）。
