# Qwen3-TTS 给干员配音 · 选型与接入方案

> 版本 v0.1（2026-11-15）｜状态：**方案待拍板，未动手安装**
> 依据：仓库 `qwen3tts/`（QwenLM/Qwen3-TTS @ 022e286）源码逐行核对 + 构建机实况（2×GTX 1080 Ti / 11 G 各、Ubuntu 26.04、36 张干员卡、网关 5500、对话实例 5701-5716、Vue 3 前端 + Android/Windows 客户端）

---

## 0. 一句话结论

**不要给每个干员训一个语音模型。** 用 **Base 模型的「克隆 prompt」给每个干员固化一套音色**，锚定音（参考音频）用 **VoiceDesign 批量生成**。

即：

```
VoiceDesign（一句中文描述 → 一条 6~10 秒样音）
        │
        ▼
Base.create_voice_clone_prompt(样音 + 台词文本)  ← 每个干员 × 每种情绪 各一个，存盘复用
        │
        ▼
Base.generate_voice_clone(任意台词, voice_clone_prompt=该干员的 prompt)
```

这条流水线 README 第 288-347 行（"Voice Design then Clone"）就是这么写的，原话是 *"especially useful when you want a consistent character voice across many lines"*——正好是我们的场景。

---

## 1. 为什么不用「每个干员训模型」

| 维度 | 训一个干员模型（LoRA/全参微调） | 固化克隆 prompt（推荐） |
|---|---|---|
| 素材门槛 | 30 分钟~数小时**干净单人**音频 + 逐字稿 | **6~10 秒 + 一句台词文本** |
| 单干员耗时 | 训练 1~4 小时（1080Ti 上更久） | **秒级**（一次 encode） |
| 产出体积 | 每干员一套权重（数百 MB~GB） | 每干员几十~几百 KB 的张量 |
| 音色一致性 | 高 | **高**（同一 prompt 喂进去，音色锁死） |
| 情绪/语气控制 | 微调能学到一部分 | **靠「多锚定音」解决**（见 §3） |
| 泛化风险 | 训坏了整张卡都怪 | 单条音不对就换锚定音，**可回滚到单条** |
| 版权 | 必须用官方声优音频 → 公开站有风险 | VoiceDesign 生成原创音色，**零版权问题** |
| 36 个干员总量 | 36 次训练 + 36 套权重要维护 | 36 × 4 条锚定音，一天能铺完 |

**关键补充（源码实证）**：`create_voice_clone_prompt` 里有硬检查 `if self.model.tts_model_type != "base": raise`——**prompt 只能由 Base 建**，VoiceDesign 只负责"造声音"，不参与固化。这也印证了官方的两段式用法。

**什么时候才考虑微调**：等你发现某 3~5 个"招牌干员"（群里最常被聊的、或者对外的门面）用克隆怎么调都不像，且能搞到 30 分钟以上高质量录音时，再对这几个单独微调（`finetuning/` 目录就是干这个的）。这是二期优化，不是一期。

## 2. 三条路线对比（同一张表看全）

| | A. Base 克隆（推荐主路） | B. VoiceDesign 实时生成 | C. CustomVoice 预设音色 |
|---|---|---|---|
| 干员音色从哪来 | 一条锚定音（自己造或官方音频） | 每次现写描述现生成 | 9 个固定音色里挑 |
| 音色一致性 | **强**（prompt 固化） | **弱**（每次都有漂移） | 强（但只有 9 种） |
| 情绪控制 | 无 instruct，靠多锚定音 | **有 instruct**（描述里写语气） | 1.7B 有 instruct、0.6B 无 |
| 每句话延迟 | 一次合成 | 一次合成（更慢，见 §7） | 一次合成 |
| 适合 | **日常台词、长句、成片** | 造锚定音、试音、特殊台词 | 配角/路人群像、兜底 |
| 结论 | ✅ 主干 | ✅ 只用来造锚定音 | ⚠️ 36 个干员不够分，留作兜底 |

## 3. 落地方案：每干员「1 主锚 + N 情绪锚」

Base 模型**没有 instruct 参数**（README 的模型表里 Base 的 "Instruction Control" 是空的，`generate_voice_clone()` 签名也没有 instruct）。所以"同一干员，冷静时和炸毛时"不能靠一句指令切换，**只能靠换参考音频**。

做法：每个干员准备一组锚定音，每种一个 prompt 文件。

```
voices/
├─ manifest.json                # 干员 → 音色/prompt 的映射表
├─ 陈千语/
│   ├─ calm.wav                 # 6~10s 锚定音（平静）
│   ├─ calm.pt                  # 对应 prompt（ref_code + spk_embedding + ref_text）
│   ├─ angry.wav / angry.pt
│   ├─ happy.wav / happy.pt
│   └─ design.txt               # 生成 calm.wav 用的那句描述（可复现）
└─ ...
```

**保存 prompt 而不是每次重算**的理由：`VoiceClonePromptItem`（`qwen_tts_model.py:41`）就四个字段——`ref_code`（张量）、`ref_spk_embedding`（张量）、`icl_mode`、`ref_text`，`torch.save()` 直接存，单条几百 KB。`generate_voice_clone(..., voice_clone_prompt=items)` 收的就是它。

**锚定音规格（很影响成败）**：
- 时长 6~10 秒（太短音色抓不住，太长推理变慢）
- 单人、无 BGM、无混响、无音效、44.1k/48k 转 24k 单声道
- 文本必须与音频**逐字对应**（ICL 模式要求 `ref_text`，写错会带坏发音）
- 一条锚定音只承载一种情绪，别用"又笑又哭"的混合句

**情绪锚的建议集合**（先做 4 条，够覆盖卡内绝大多数台词）：`calm`（默认/叙述）、`angry`（对抗/生气）、`happy`（轻松/撒娇）、`soft`（低声/关心）。哪条没有就回落到 `calm`。

## 4. 锚定音从哪来（这是真正的数据问题）

### 4.1 首选：VoiceDesign 生成（零素材，可批量）

每个干员写一句中文描述 → 出一段"该干员的典型台词"当锚定音。示例（以陈千语这类活泼人设为例）：

> 描述：`年轻女性，音色明亮偏脆，语速偏快，句尾上扬带笑意，情绪外放但不尖锐，略带少年感。`
> 样句：`博士——今天的训练我全做完了，现在陪我出去转一圈，就一圈。`

36 个干员的描述可以从 `characters_v2/*.json` 的人设直接反推（性格、年龄、语域），**这张描述表是这份方案里唯一必须人工过一遍的内容**（我可以先按人设批量起草 36 条，你听样音再调，改一句重出一段，成本极低）。

优点：零版权风险、完全可控、能"设计"出比官方更贴合卡内人设的音色。
缺点：不等于官方声优，玩家可能觉得"不像"。

### 4.2 备选：官方语音克隆（效果最好但有风险）

拿游戏内语音当锚定音，音色最"像"。但要注意：
- **版权/声优权益**：BakerAI 是公开站（chat.peilika.beer、APK 分发），把官方声优的声音克隆成可无限合成的模型，有被投诉/下架的实际风险。你定的红线是"辱华不做"，这条不在红线内，但属于**要提前想清楚**的一类。
- **素材清洗成本**：游戏语音普遍带 BGM/音效/短促台词，逐条清洗 36 个干员的工作量远大于生成。
- **语言漂移**：官方语音以日语为主，克隆后合成中文长句，音色有漂移风险（跨语种克隆是它的宣传点，但实测仍需验证）。

**建议**：一期用 4.1 全量铺；如果试听下来对某几个门面干员不满意，再单独决定要不要走 4.2，并且**只在客户端内使用/不对外分发音频**，风险小一些。

### 4.3 陈千语语音包实测（2026-11-15，`D:\陈千语语音包`）

这是**目前唯一一份真实素材**，先盘清再决定要不要训。

| 项 | 实测 |
|---|---|
| 文件 | 79 个 wav（PCM 16bit 48 kHz 单声道）+ 79 个 mp3（**同一批内容的另一份编码**，总时长完全相同 527.99 s） |
| 唯一内容 | **79 条 / 8.8 分钟** |
| 文对 | `mp3/改名对照表.txt` 是 79 行 TSV（编号 001-079 / 条目名 / 解锁条件 / 文件名 / 台词），**与 `DM_20261004230402_001.wav … _079.wav` 严格对应，不缺一条**——省掉 ASR 对齐 |
| 时长分布 | <1.2 s：**21 条**（合计 16 s，技能音「断！」「看剑！」，**不建议进训练集**）；1.2~15 s：42 条（3.0 分钟）；>15 s：16 条（16~30 s 的长独白，质量最高，训练时要切段） |
| 语速 | 3.3~5.2 字/秒，正常偏快 |
| 情绪覆盖 | 偏「元气/战斗」，**缺平淡叙述**——日常台词容易偏冲 |

**结论：能训，但 8.8 分钟只够 LoRA；全参微调会过拟合，且 1080Ti 装不下。**

- 全参微调显存账：1.93B 参数 → fp16 权重 3.9 G + 梯度 3.9 G + AdamW 的 fp32 master 7.7 G + 两个动量 15.4 G ≈ **31 G**（还没算激活）。11 G 单卡不可能，也不建议在 2×11 G 上硬凑。
- LoRA 账：权重 3.9 G（冻结）+ 少量适配器 + 短序列激活 ≈ **6~8 G**，单卡可行；产物体积只有几十 MB。
- 但这 8.8 分钟**更值钱的用法是当克隆锚定音**：Base 的 3 秒克隆用的是「原音条件」，不是「学出来的规律」；在 8.8 分钟这个体量下，训练几乎不可能超过直接用原音克隆。

**现成的最佳锚定音候选**（3~10 s、语速正常、文本信息量足）：

| 编号 | 时长 | 文本开头 | 用途 |
|---|---|---|---|
| 013 | 6.58 s | 管理员！我——嗯？走流程？哦，懂了懂了……前来报到 | 主锚（最完整、最标准） |
| 019 | 6.68 s | ……哇！差点没看到你，管理员！嘿嘿，刚才我在琢磨新想到的剑招 | 主锚备选（更活泼） |
| 025 | 8.95 s | 我们常说"礼轻情意重"。倘若真的心怀情意…… | 平静锚（唯一语速慢的） |
| 047 | 6.06 s | 圆又圆，亮晶晶……原来醚质是这个大小啊。 | 轻声/好奇锚 |
| 001 | 3.80 s | 准备？嘿，我的剑可没有懈怠的时候！ | 战斗锚 |

（对应音频 `D:\陈千语语音包\DM_20261004230402_013.wav` 等；文件名编号 = 对照表编号。）

## 5. 工程侧：服务怎么摆

### 5.1 服务形态

新增一个独立 Python 服务（**不进 gateway 进程**，避免把 1.7B 模型塞进已经有 8 千行上帝模块的后端）：

| 项 | 值 |
|---|---|
| 端口 | `5970`（正式）/ `5971`（测试）——现有端口段 5500/5601-5708/5810/5900-5930/8200 之外，不冲突 |
| 进程 | `systemd --user`（跟 `perlica-*` 一样的托管方式） |
| 代码目录 | `/run/media/y/游戏/baker/tts/`（与 backend 平级，**不放 / 上，那里只剩 26 G**） |
| venv | `/run/media/y/游戏/baker/tts/venv`（独立，不碰后端 venv） |
| 模型权重 | 放 `/run/media/y/游戏/baker/tts/models/`（253 G 空闲），Base + VoiceDesign 各 4.5 G |
| 显存 | fp16 各占约 4.5 G；GPU0 放 Base、GPU1 放 VoiceDesign（RAG 已占 1.4 G/0.7 G，仍有余量） |
| 并发 | **单队列**（`max_batch=1` + 排队），1080Ti 上别开并发，只会互相拖慢 |

### 5.2 接口契约（草案）

```
GET  /health                     → {"ok":true,"model":"1.7B-base","device":"cuda:0","rtf":0.0}
GET  /voices                     → [{"char":"chenqianyu","emotions":["calm","angry","happy","soft"]}]
POST /tts
     {"char":"chenqianyu","emotion":"calm","text":"……","format":"wav","speed":1.0}
     → 200 audio/wav（整段）
POST /tts/batch                  → {"items":[{char,emotion,text}...]} → 逐条 wav（长文本一次性排队）
POST /voices/{char}/{emotion}    → 上传/重建锚定音（管理用，带 token）
```

**不做 SSE 流式**（这个开源包没有真流式，见 §7），前端按"整句请求 → 整句播放"处理。

### 5.3 文本侧配合（很重要）

`worldview.txt` 现在要求模型**纯文本输出**，这对 TTS 正好：拿到的回复没有 Markdown 噪音。前端/网关侧加一层预处理：

1. 去掉 `（）` 内的旁白、`*动作*`、emoji
2. 按 `。！？…；\n` 切句，单句 ≤ 40 字（长句切两段，音频自然度明显更好）
3. 每句请求 `/tts`，**按顺序播放**，第一句播完时后面的一般已经回来了

### 5.4 前端（Vue 3 / 客户端）

- 一期内测先做**「点一下，播这条回复」**按钮（不需要实时，用户可接受 2~4 秒等待）
- 二期做**自动播**：回复开始流式到达时就开始切句请求，保证"她还在说话时下一句已经在合成"
- 必须支持**打断**：切角色/切会话/用户发新消息 → 立刻 `audio.pause()` + 取消队列里未播的句子
- 群聊：多个干员依次发言 → 每段用各自的 prompt，串行合成

## 6. 构建机上必须先解决的三个坑（否则装完跑不起来）

1. **torch 必须是 cu126 版，且 ≤ 2.7.1**
   PyTorch 2.8 起砍掉 Pascal（sm_61），cu128 版更是从 sm_60 就没有；`pip install torch` 默认装最新版 → 报 `no kernel image is available for execution`。
   正确姿势：`pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu126`
2. **不要装 flash-attn**
   FA2 只支持 sm_80+，Pascal 装了也报 `FlashAttention only supports Ampere GPUs or newer`。加载模型时必须 `attn_implementation=None`（demo 的 `--no-flash-attn`）。
3. **dtype 用 fp16，不要照抄 README 的 bf16**
   Pascal 没有原生 bf16。1.7B fp16 约 4.5 G，fp32 约 9 G（加 RAG 后爆显存）。

其余安装项：`transformers==4.57.3`、`accelerate==1.12.0`、`librosa`、`soundfile`、`onnxruntime`、`einops`；`sox` 需要系统装 `libsox-fmt-all`（`apt install sox libsox-fmt-all`）。

## 7. 性能：必须先量，不能拍脑袋

**已知的坏消息**：`.py` 全仓搜 `yield` = **0 处**，三个 `generate_*` 全部返回 `(List[np.ndarray], int)` 整段音频。`non_streaming_mode` 的 docstring 原话：

> *"this option currently only simulates streaming text input when set to `false`, rather than enabling true streaming input or streaming generation."*

**意思是**：宣传的 97 ms 首包是线上 API 的能力，**开源包没有流式输出**。所以延迟只能靠"切句 + 排队"逼近，不能靠流式。

**算力账（也是坏消息）**：Talker 主干 1.7B + CodePredictor（5 层/1024）+ 12 Hz 编解码、`num_code_groups=32` → **每 1 秒音频要跑 12×32 = 384 个 token 步**，而且 Pascal 没有 tensor core。

**所以要实测这四个数**（判定线在右）：

| 指标 | 判定线 | 不达标怎么办 |
|---|---|---|
| RTF（合成 1 s 音频耗时） | ≤ 1.0 可做自动播；≤ 2.0 只能按需点播 | 换 0.6B（约 2.5 倍速度）或降级点播 |
| 单句（15 字）端到端延迟 | ≤ 4 s | 同上 |
| 单模型显存峰值 | ≤ 9 G | 调低 `max_new_tokens`、缩短锚定音 |
| 音色相似度（人耳 A/B） | 同 prompt 两次差异小到听不出 | 加大锚定音时长 / 改 ICL 模式 |

**我的预估**：RTF 落在 **0.8~3.0**。>1.5 就得考虑 0.6B 或"按需点播"。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 1080Ti 上 RTF > 2 | 不能自动播 | 点播模式；或 0.6B；或常用台词预生成缓存 |
| 克隆音"忽好忽坏" | 体验差 | 每个干员锚定音定 2 次采样挑稳的；`temperature` 从 0.9 往下调（0.7~0.8 更稳，但会略平） |
| 官方语音版权 | 下架风险 | 一期只用 VoiceDesign 原创音色；官方音频仅内部试听 |
| 单队列排队 | 群聊卡顿 | 按干员预算：群聊里只给"发言人"配音，旁白不配 |
| `/` 只剩 26 G | 装不下 | 权重、venv、缓存全放 `/run/media/y/游戏/` |
| 服务挂了拖累聊天 | 聊天不可用 | TTS 完全旁路：超时 3 s 直接静默降级为纯文本，**绝不阻塞聊天主链** |
