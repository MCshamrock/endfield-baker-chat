# 验收与自测

> 目标：任何人拿到这份工程，都能在半小时内把「前端 × 新后端」跑起来并确认没坏。
> 下面的命令按 Windows PowerShell 写；路径以本机为例。

---

## 1. 起后端（`web/back`）

后端已经在本机跑着的话跳过这节，先确认：

```powershell
curl http://127.0.0.1:5660/readyz
# {"ok":true,"db":"mysql","schema":"1","migrations":"017_user_role"}
```

从零起（详见 `web/back/README.md`）：

```powershell
cd F:\dshworkspace\BakerAI\BakerAI_new\web\back
pwsh -File scripts\dev_mysql.ps1 start          # 便携版 MySQL 8.4（端口 3307）
.venv\Scripts\python.exe scripts\migrate.py     # 幂等，跑到 017
.venv\Scripts\uvicorn.exe app.main:app --host 127.0.0.1 --port 5660
```

> 已经验证过的备选：WSL 里的 Linux venv（`.venv-linux`）+ 用户态 MySQL，
> 一键脚本在 `BakerAI_new/local-client/启动.bat`，说明见
> `web/back/docs/13-本地联调清单.md` §5.5。

> 后端若在本次改动前就已经起好，需要重启一次才能让 `imports/normalize.py` 的
> 1 行补丁生效（weighted 群聊导入不被降级）：
> `wsl -e bash -lc "bash /mnt/f/dshworkspace/BakerAI/BakerAI_new/_runtime/wsl_backend_run.sh"`。

## 3. 自动自测（不花上游额度）

```powershell
node scripts/claim-smoke.mjs      # 取件码：自带假后端，不需要真后端
node scripts/contract-smoke.mjs
node scripts/adapter-e2e.mjs
node scripts/group-e2e.mjs
```

| 脚本 | 覆盖 | 期望 |
|---|---|---|
| `claim-smoke.mjs` | 上传（含 413/507/400/429 文案映射）/ 验码（404/410/本地格式）/ 领取（摘要、`duplicate`、401）/ 注册带码（`claim_code`、`bad_claim_code` 回滚）/ 注册后读导入记录 | `39 PASS / 0 FAIL` |
| `contract-smoke.mjs` | 设备注册 / meta / characters / 建会话 / 历史导入 / 读消息 / 只存不发（幂等）/ 附件上传与去重 / 注册→me→登出→登录 / 改密与旧密码错 | `27 PASS / 0 FAIL` |
| `adapter-e2e.mjs` | 中间层真实逻辑：第一次对话触发历史导入、请求体**没有** history、usage 映射、绑定复用、成功后幂等键更新、图片上传为附件、base64 不重发 | `16 PASS / 0 FAIL` |
| `group-e2e.mjs` | 群聊：建群（weighted）/ 历史导入+说话人保留 / 一轮三人 / assign 指定 / 权重 PUT 与夹取 | `24 PASS / 0 FAIL` |

说明：`adapter-e2e.mjs` 用 esbuild 现场打包 `src/utils/backend.ts`，只拦截
"真正生成回复"的那一次 POST（返回假回复），其余请求全部打真后端。

`claim-smoke.mjs` 默认起一个 Node 假后端（随机端口）实现契约里的 4 个端点，
再把 `src/utils/cloudData.ts` / `auth.ts` 用 esbuild 打进临时模块**直接调用**——
测的是界面里真正跑的请求构造函数，不是另写一份 fetch。
真后端就绪后补跑：`node scripts/claim-smoke.mjs --live`（或 `BAKER_BACKEND=http://ip:port`）。

## 4. 界面验收（手工，8 分钟）

1. 浏览器打开 <http://localhost:5173>。
2. 有公告/更新弹窗就先点「确定 / 不再提醒」。
3. 右上操作带点齿轮 → 侧栏第一项「账号」。
   - 访客态应看到：说明文字、「登录 / 注册」两个按钮、用户名/密码输入框。
4. 注册一个新账号（用户名 2–20 字，中文/字母开头；密码 ≥8 位）：
   - 成功后变成「当前账号：昵称」+ 名下设备列表 + 「退出登录」+ 修改密码。
5. 「退出登录」→ 回到访客态；再「登录」同一账号 → 又变回账号态。
6. 回到聊天页，随便发一句话：
   - 应正常回复；括号描写/沉浸式跟随设置；
   - DevTools → Network 里应看到 `POST /v1/conversations/{id}/messages`，
     **请求体里没有 `history`**。
7. 发一张图：`POST /v1/attachments` 先出现，然后消息请求带 `attachment_id`。
8. 打开输入推荐面板：应发出 `POST /v1/conversations/{id}/suggestions`，返回 3 条。
9. 建一个群（3 人）发一句：应看到 `POST /group/session`、`POST /group/reply`。
10. 群聊页点「+」建群：勾 3 人 → 创建 → 立刻弹出**「发言权重」**（3 条滑杆）。
11. 控制台不应有 error（本机实测：0）。

> 想用无头浏览器复现第 3–5 步：`BakerAI_new/_runtime/tmp/ui_smoke.mjs` 是一份
> CDP 脚本（打开页面 → 关弹窗 → 开设置 → 切账号页 → 注册测试账号 → 填表登录 →
> 断言「当前账号」「退出登录」出现 → 截图）。它属于一次性验证工具，没进工程。

## 5. 与 `docs/13-本地联调清单.md` 的对应

后端那份 13 条是拿**改装老客户端**验的；这份前端走 `/v1`，对应关系如下：

| # | 老客户端怎么验 | 本前端怎么验 | 备注 |
|---|---|---|---|
| 1 | 单聊非流式 | 发一句话 | 走 `/v1/messages`，不再传 history |
| 2 | 单聊流式 | 设置里打开流式再发 | 走 `/v1/messages:stream`，帧名与旧版一致 |
| 3 | 沉浸式 | 开/关各发一句 | 服务端后处理（`immersive` 字段） |
| 4 | 图片 | 发一张图 | 走 `/v1/attachments` + `attachment_id` |
| 5 | 历史图不回放 | 连发两轮 | 请求体里根本没有 base64 |
| 6 | 输入推荐 | 点开推荐面板 | `/v1/suggestions`（无请求体） |
| 7 | 建群 | 建 3 人群 | `/group/session` |
| 8–11 | 群聊四种模式 / 话题 / 关群 | 同老客户端 | 群聊协议不变 |
| 12 | `/instances` | `curl http://127.0.0.1:5660/instances` | 运维端点仍在 |
| 13 | `/v1/meta` | 设置里「测试连接」 | 会显示 `web_search=false` |

差异（不是 bug）：

- 老客户端的"联网搜索"开关在本前端仍然存在，但新后端不做联网搜索，字段会被忽略；
- 老客户端把图放在 `history[].image`，本前端当前轮也这么传，**中间层转成附件**；
- 群聊仍是老协议（有新后端实现），不是 `/v1`，原因见 `01-中间层适配.md` §4.2。

## 6. 构建验收

```powershell
npm run build
# vue-tsc --noEmit（0 错误）→ vite build → dist/
```

本机实测：`built in 8.22s`，主包 1.16 MB（gzip 444 KB），只有既有的
"chunk > 350 kB" 提示（原前端也一样，不是这次引入的）。

`dist/` 是纯静态文件；同源部署时把 `/v1`、`/group` 反代到 5660 即可
（nginx 注意 SSE：`proxy_buffering off; proxy_read_timeout 600s;`）。
